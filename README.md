# URL Shortener API

A URL shortening service built with Java, Spring Boot, and PostgreSQL. Short codes are generated by Base62-encoding the database-assigned id, with optional custom codes and per-click analytics.

**Stack:** Java 17+ · Spring Boot 4 · PostgreSQL · Spring Data JPA · JUnit 5 / Mockito · MockMvc · Docker

## Getting started

```bash
git clone git@github.com:yourusername/url-shortener-api.git
cd url-shortener-api
docker compose up -d
./mvnw spring-boot:run
```

API available at `http://localhost:8080`. Run tests with `./mvnw test` (requires the database container to be running).

## Usage examples

**Shorten a URL**
```bash
curl -X POST http://localhost:8080/shorten -H "Content-Type: application/json" \
  -d '{"originalUrl": "https://www.example.com/some/very/long/path"}'
```
```json
{ "shortCode": "21", "originalUrl": "https://www.example.com/some/very/long/path", "createdAt": "..." }
```

**Shorten with a custom code**
```bash
curl -X POST http://localhost:8080/shorten -H "Content-Type: application/json" \
  -d '{"originalUrl": "https://www.github.com", "customCode": "mygh"}'
```

**Follow the short link** (returns a 302 redirect and records the click)
```bash
curl -i http://localhost:8080/mygh
```

**Get usage stats**
```bash
curl http://localhost:8080/mygh/stats
```
```json
{ "shortCode": "mygh", "originalUrl": "https://www.github.com", "totalClicks": 3, "clickTimestamps": ["...", "...", "..."] }
```

| Method | Endpoint | Description |
|---|---|---|
| POST | `/shorten` | Create a short URL (optional `customCode`) |
| GET | `/{code}` | Redirect to the original URL, tracks the click |
| GET | `/{code}/stats` | Click count and timestamps |

## Design notes

- **Short code generation**: auto-generated codes are the database id encoded in Base62 (`0-9a-zA-Z`), guaranteeing uniqueness by construction instead of relying on random generation with collision checks. This requires saving the entity in two steps — once to obtain the id, once more to persist the computed code.
- **302, not 301**: redirects are temporary (302) rather than permanent, so browsers don't cache the redirect client-side — every click reliably hits the server and gets recorded for analytics.
- **Custom codes** bypass the Base62 flow entirely and are validated for uniqueness before creation.
